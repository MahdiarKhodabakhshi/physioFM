# PhysioFM — Experiment Log (lab notebook)

A chronological, agent-agnostic record of **every experiment**: why it was run,
exactly what was run, its result (dated), the running agent's interpretation, and
a slot reserved for **Mahdiar** to confirm or correct that interpretation. This
exists because the project is driven by several coding agents (Claude Code,
Cursor, Codex) and the human needs one place to see the latest progress and the
*reasoning* behind it without reverse-engineering commits.

**Relationship to `docs/PHASE*.md`:** the phase docs are the curated, thematic
*results* (locked claims, final tables). This log is the *journal* — one entry per
experiment, in time order, including dead ends. When an entry resolves a phase
question, mirror its verdict into the matching `docs/PHASE*.md` table and link
back here.

## How to use it

**One file per experiment:** `EXP-NNNN-short-slug.md`, scaffolded from
[`TEMPLATE.md`](TEMPLATE.md). Each file carries YAML frontmatter that is the
**single source of truth** — the index table below is regenerated from it, so it
never drifts.

**Claude Code:** run `/experiment` (the `experiment-log` skill). It assigns the
next ID, stamps the date, gathers candidate commits, and rebuilds the index.

**Cursor / Codex / by hand:** copy `TEMPLATE.md` to the next `EXP-NNNN-*.md`, fill
the frontmatter + sections, then run the helper to refresh the index:

```bash
python docs/experiments/exp.py new --title "..." --agent cursor
python docs/experiments/exp.py index    # after editing any entry
python docs/experiments/exp.py check     # find unfinished/unverified
```

## Rules (so the log stays trustworthy)

1. **Create the entry when the experiment is *decided*, not after** — so the *why*
   is captured before results bias it. Status starts `planned`/`running`.
2. **Date every result** (`run_date` in frontmatter + §4 header). Convert relative
   dates to absolute.
3. **§5 Interpretation is the agent's claim. §6 is Mahdiar's only.** Agents never
   tick §6 or set `verified: yes` — only the human does, after checking.
4. **Record real outcomes**, including failures and nulls. A null is a result.
5. **List the commits** that implement the experiment and its write-up (§7).
6. **Regenerate the index** (`exp.py index`) after any frontmatter change.

## Frontmatter fields

`id` · `title` · `status` (planned|running|done|blocked) · `created` · `run_date`
· `agent` · `phase` · `verified` (no until Mahdiar confirms) · `tags` · `commits`
· `verdict` (one-line takeaway shown in the index).

## Section layout of each entry

1. **Why** — hypothesis & motivation · 2. **Setup** — exact commands/config ·
3. **Status & run log** · 4. **Results** (dated) · 5. **Interpretation** (agent) ·
6. **✅ Your verification** (reserved for Mahdiar) · 7. **Commits** · 8. **Links**.
